# AeroMusic Player (AMP)

文化祭など、**BGM と効果音を同時に出す**ための多重再生プレイヤーです。
mp3 / wav / flac / ogg / m4a / aac / opus に対応。

---

## 起動方法は2つあります

### ① .exe 版（おすすめ）
**[Releases](https://github.com/Orahu01/AeroMusicPlayer/releases/latest) から `AeroMusicPlayer-Setup-x.x.x.exe`（インストーラ）または
`AeroMusicPlayer-x.x.x-portable.exe`（インストール不要）をダウンロード**して実行するだけです。
黒い窓は出ません。設定 の「アップデート」から**ソフト自身で新しいバージョンに更新**できます
（起動時にも自動でチェックします）。

### ② Web 版（ソースから直接動かす場合）
**`AMP.bat` をダブルクリック**します。黒いウィンドウ（サーバ）と、
アドレスバーのない専用ウィンドウ（AMP 本体）が開きます。

> ⚠️ **黒いウィンドウは閉じないでください。** 閉じると音も止まります。
> AMP 本体のウィンドウを閉じれば、黒いウィンドウも自動で終了します。

どちらの版でも、初回のみ「マイクの使用を許可しますか？」と聞かれることがあります。
これは **出力デバイスの一覧を表示するために Chrome / Electron が要求する仕様**で、
許可した瞬間にマイクは停止し、録音は一切行いません。許可しないと
出力先が「既定のデバイス」しか選べなくなります。

---

## 3つの出力を別々のデバイスへ出せます

AMP は音声を **3系統の独立したバス**に分けて出力します。
それぞれ **出力先デバイスを一覧から自由に選べます**（Voicemeeter でも、
スピーカーでも、ヘッドホンでも、USB オーディオでも何でも構いません）。

| バス | 中身 | おすすめの出力先 |
|---|---|---|
| **BGM** | 各デッキの曲 | `VoiceMeeter Input (VAIO)` |
| **SE** | パッドの効果音 | `VoiceMeeter Aux Input (AUX VAIO)` |
| **試聴 (Cue)** | 次の曲の下見・パッドの試聴 | **ヘッドホン**（Voicemeeter を通さない） |

設定は右上の **「設定」**から。
Voicemeeter が入っていれば、初回起動時に自動で検出して BGM→VAIO / SE→AUX に設定します。

### Voicemeeter Banana 側の設定例

```
                     ┌──────────────── Voicemeeter Banana ────────────────┐
  AMP  BGMバス ─────▶│ Virtual Input (VAIO)   ── fader ─┐                 │
  AMP  SEバス  ─────▶│ Virtual Input (AUX)    ── fader ─┼─▶ A1: スピーカー │──▶ 会場
  マイク  ──────────▶│ Hardware Input 1       ── fader ─┘                 │
                     └───────────────────────────────────────────────────┘

  AMP  試聴バス ────────────────────────────────────────▶ ヘッドホン（直結）
```

こうすると Voicemeeter のフェーダーで **BGM・SE・マイクを本番中に個別に上げ下げ**できます。
AMP 側にも音量スライダー・ミキサー（下記）があるので、二重に音を作り込めます。

> Voicemeeter を使わない場合は、3つとも同じスピーカーを選べば普通に鳴ります。
> **AMP は Voicemeeter を内蔵しているわけではありません。**
> Windows に仮想出力デバイスとして登録される部分（＝ Voicemeeter の心臓部）はドライバの領域なので、
> ブラウザ上のアプリからは作れません。マイク入力やPA本線は今まで通り Voicemeeter に任せ、
> AMP は「BGM・SEを鳴らして Voicemeeter に渡す高性能プレイヤー」という役割分担が、遅延の面でも一番安定します。

## BGM の使い方（左側）

### 曲を入れる
- **エクスプローラーから曲をドラッグ＆ドロップ** → プレイリストに追加
- **フォルダ** → フォルダごと一括読み込み（サブフォルダも探します）
- **＋ 追加** → ファイル選択ダイアログ

ダウンロードした mp3 をそのまま放り込んで大丈夫です。

### デッキ（数は自由に増減できます）
BGM 欄の **−／＋** でデッキを 1〜6 枚まで増減できます。
複数デッキがあると、1つで曲を流しながら他のデッキに次の曲を仕込めます。

| 操作 | 説明 |
|---|---|
| プレイリストの曲にマウスを乗せて デッキ名ボタン（**A**, **B**…） | そのデッキに曲を読み込む |
| 曲を**ダブルクリック** | 空いているデッキに読み込んですぐ再生 |
| **試聴** | **試聴バス**（ヘッドホン）だけで下見再生。会場には出ません |
| ▶ / ❚❚ / ■ | 再生・一時停止・停止 |
| **F/I** | フェードインしながら再生 |
| **F/O** | フェードアウトしながら停止 |
| **⇄** | 今鳴っている曲たちからこのデッキへその場でクロスフェード |
| **LOOP** | その曲をループ |
| 波形バーをクリック / ドラッグ | 頭出し（シーク） |
| **VOL** | そのデッキだけの音量 |

デッキをクリックすると「選択中」になり、`Space` で再生 / 一時停止できます。

### AUTO MIX
オンにすると、曲の残りがクロスフェード秒数を切った時点で
**空いているデッキに次の曲を自動で用意して繋ぎます。** 曲間が途切れません。

## 効果音（SE）の使い方（右側）

### 音を入れる
- **パッドに直接ドラッグ＆ドロップ**（複数まとめてドロップすると連続したパッドに入ります）
- 空のパッドを**クリック**してファイル選択
- **一括読込** → フォルダ内の音を先頭から順にパッドへ流し込む

読み込んだ時点でメモリ上に展開されるので、**押した瞬間に鳴ります。**
パッドの数・列数も上部の **列／−／＋** で自由に変更できます（最大63個）。

### 鳴らす
- パッドを**クリック / タップ**
- パッド右上に表示された**キーボードのキー**を押す（`1`〜`0`, `Q`〜`P`, `A`〜`;`, `Z`〜`/`）

**同じ音を連打しても重なって鳴ります**（拍手・銃声など）。
BGM とも当然同時に鳴ります。同時発音は最大 64 音。

### パッドの設定（**右クリック**）

| 項目 | 説明 |
|---|---|
| 表示名 | パッドに表示される名前 |
| ショートカットキー | 好きなキーに割り当て直せる |
| **重ねて再生** | 連打すると音が重なる（拍手・効果音向け） |
| **鳴らし直し** | 前の音を止めて鳴らし直す（ジングル・セリフ向け） |
| **押すたび再生/停止** | トグル。ループと組み合わせて環境音に |
| **押している間だけ** | 押している間だけ鳴る |
| 音量 | そのパッドだけの音量 |
| 停止フェード | 止めるときのフェード時間（ブツッと切れるのを防ぐ） |
| ピッチ / 速度 | 0.5〜2.0倍 |
| ループ | 繰り返し再生 |
| 色 | 見分け用の帯（左端に表示） |

**SE停止** で効果音だけを一括停止できます（BGM は止まりません）。

### パッドだけを別ウィンドウに切り出す（SuperDisplay 運用）

**「別窓」**ボタンを押すと、**効果音パッドだけの操作画面**が新しいウィンドウで開きます。
これを SuperDisplay 経由でタブレット側の画面にドラッグして持っていけば、

- **タブレット側**：SEパッドをタップして操作する専用パネルに
- **ノートPC側**：BGM・ミキサー・出力設定など本体側の操作に

…と役割を分けられます。裏では `BroadcastChannel` という仕組みで
同じ Chrome プロセス内の2つの画面がリアルタイムに繋がっているので、
タブレット側で叩いた音は**ノートPC本体からそのまま出力されます**
（タブレット自体はスピーカーに繋がっている必要はありません）。
本体（AeroMusicPlayer の方）を閉じると音も止まる点は変わりません。

## ミキサー（音質調整）

上部の **「ミキサー」**から、BGM / SE それぞれに次を掛けられます。

- **3バンド EQ**（ローカット・LOW・MID・HIGH）
- **コンプレッサー**（スレッショルド・レシオ・メイクアップ、下のバーでかかり具合を表示）

初期状態はすべて **OFF（素通し）** です。ここは「音を追い込む」用の最小限の調整に留めています。
本格的な音作りやマイクへの処理は、今まで通り Voicemeeter 側にお任せください。

---

## 全体の音量

画面上部に **BGM / SE / 試聴** それぞれの
**独立した音量スライダーとレベルメーター**があります。`M` でミュート。

### DUCK（ダッキング）
オンにすると、**効果音が鳴っている間だけ BGM が自動で下がり**、
鳴り終わると元に戻ります。アナウンスやセリフを聞かせたいときに便利です。
下げ量（既定 -9dB）と戻り時間は 設定 で変更できます。

## 見た目

初期は白背景・黒枠のシンプルな配色です。右上の **◐** ボタンで黒基調に切り替えられます
（設定は自動保存されます）。

## ショートカット

| キー | 動作 |
|---|---|
| `Space` | 選択中のデッキを再生 / 一時停止 |
| `Tab` | 操作対象のデッキを切り替え |
| `Esc` | **全停止（パニックボタン）** |
| `1`〜`0` `Q`〜`P` `A`〜`;` `Z`〜`/` | 効果音パッド |
| 右クリック（パッド上） | パッド設定 |

## 設定と音は自動で保存されます

- **パッドの音源そのもの**がブラウザ内に保存されるので、
  次に起動したときは**そのまま同じ音が入った状態で立ち上がります**（再設定不要）。
- プレイリストは **フォルダ** で読み込んだ場合に復元されます。
  起動時に「フォルダを再接続」ボタンが出たら押してください。
- 音量・EQ・ダッキング・出力先・デッキ数・パッドの色やキー割当もすべて保存されます。

> **別の PC に丸ごと持っていきたいとき**
> このフォルダごと（自動生成される `.amp-profile` フォルダを含めて）コピーすれば、
> 設定も効果音も入った状態で動きます。

## 本番前チェックリスト

1. `AMP.bat` を起動
2. 設定 → 出力先が BGM / SE / 試聴 とも意図した通りか確認
3. Voicemeeter の A1（出力先スピーカー）が合っているか確認
4. **BGM を1曲流しながら、効果音を数発叩いて同時に出ることを確認**
5. `Esc`（全停止）が効くことを確認 ← 事故ったときの命綱
6. マスター音量を本番の位置に決めておく
7. PC の音量ミキサーで Chrome がミュートになっていないか確認
8. SuperDisplay でパッドを別窓運用する場合は、本体を閉じないことを再確認

## うまくいかないとき

**音が出ない**
→ 設定 の出力先を確認。Voicemeeter を選んでいる場合は Voicemeeter 側の
A1 出力とフェーダーも確認してください。まずは3つとも「Windows の既定デバイス」に
戻すと切り分けできます。

**出力デバイスの一覧に何も出ない / 名前が空欄**
→ 設定 の「出力デバイス名を取得する」を押してマイク権限を許可してください。

**効果音の反応が少し遅い**
→ Voicemeeter の `Menu → System Settings / Options` で
`Preferred Main SampleRate` を PC の設定と揃え、`Buffering (WDM)` を
512 → 256 程度に下げると改善します。画面下の「遅延」欄で実測値が見られます。

**Voicemeeter を再起動したら音が出なくなった**
→ AMP が自動で検出して出力先を貼り直します。戻らない場合は 設定 →
「デバイス一覧を更新」→ 出力先を選び直してください。

**「別窓」がポップアップブロックされる**
→ 初回だけ Chrome がブロックすることがあります。アドレスバー右のアイコンから
このサイトのポップアップを許可してください。

**ポート 8777 が使用中と出る**
→ AMP が既に起動しています。二重起動はできません。
どうしても変えたい場合は `amp-launch.ps1` の `$PORT` を書き換えますが、
**ポートを変えると保存済みの設定・効果音は引き継がれません。**

## ソフトの実体について

AMP は **Web技術（HTML/CSS/JS）で作ったローカルアプリ**です。
Web版・.exe版のどちらも、裏で小さなローカルサーバ（自分のPC内・127.0.0.1）を起動して
画面を表示する構成で、外部のインターネットには接続しません（アップデートの確認を除く）。

- **署名について** → .exe には署名していません。初回起動時に Windows の SmartScreen 警告が
  出ることがありますが、「詳細情報 → 実行」で進められます。個人・身内配布の範囲では
  これで問題ありません。
- **リポジトリ** → https://github.com/Orahu01/AeroMusicPlayer （MIT License）

### 開発者向け：.exe を自分でビルドする

```bash
npm install
npm run start    # 開発時にそのまま起動して確認
npm run dist     # dist/ に インストーラ(.exe) と ポータブル版(.exe) を作る
npm run release  # ビルドして GitHub Releases に公開（要 gh auth login）
```

`package.json` の `"version"` を上げてから `npm run release` を実行すると、
新しいバージョンが GitHub Releases に公開され、既に配布済みの .exe が
起動時の自動チェックでそれを検知 → ダウンロード → ユーザーが「再起動して適用」を押した
タイミングで入れ替わります（強制的に落ちて中断することはありません）。

> Windows でビルドする場合、`winCodeSign`（署名ツール一式）に含まれる macOS 用ファイルの
> 展開でシンボリックリンク作成の権限エラーが出ることがあります。これは Windows の
> 「開発者モード」を有効にすると解消しますが、必須ではありません
> （`package.json` の `win.signAndEditExecutable: false` により、この環境では既に回避済みです）。
